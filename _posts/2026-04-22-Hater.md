## 초기 기획 변경점

## Thread safe Singleton 아키텍처

게임에서는 다양한 매니저(싱글톤 객체)가 사용됩니다. 각 매니저의 코드에서 싱글톤 생성 코드를 작성하는 것은 불필요한 코드 중복을 발생시키고 이로 인한 유지 보수의 어려움을 만듭니다. 이에 제네릭 베이스 클래스로 싱글톤 코드를 분화하고 이를 상속 받는 방식을 사용했습니다. 특히나 자신을 타입 파라미터로 넘기며 부모 클래스를 상속하는 CRTP 패턴을 통해 매니저마다 정적 인스턴스 필드를 할당하고 `GameManager.Instance.StartGame()`과 같이 별도의 캐스팅 없이 직접 접근 가능한 타입 안전성을 확보하고자 했습니다. 또한 일반적인 싱글톤 생성 코드에 상호 배제를 위한 코드를 추가하는 것으로 추후 멀티 스레드 사용이 가능한 환경으로 확장 시에 인스턴스 중복 생성을 방지했습니다.

```csharp
public class Singleton<T> : MonoBehaviour where T : MonoBehaviour
{
    private static T _instance;
    private static readonly object _lock = new object();

    public static T Instance
    {
        get
        {
            lock (_lock)  // 상호 배제
            {
                /* 싱글톤 생성 */
            }
        }
    }
}
```

다만 에디터에서 계층 정리를 위해 각 매니저를 하나의 부모 오브젝트로 묶은 결과, Unity의 내부 제약으로 인해 DontDestroyOnLoad가 동작하지 않았습니다. 해당 부모 오브젝트에 싱글톤 컴포넌트를 추가할 수도 있습니다. 하지만 해당 방법은 결국 각 Scene에서 매니저의 기능 활용을 위해 매니저 이름을 기반으로 Find 메서드를 호출하고 이를 캐싱하는 작업이 필요했습니다. 이는 곧 매니저의 기능을 활용하는 각 코드에서 캐싱을 통해 싱글톤 패턴을 수동으로 재구현하는 것과 동일했고 도리어 안전성을 상실함을 의미했기에 싱글톤 객체로 생성할 객체에게 부모가 있다면 그 관계를 끊는 방식으로 코드를 수정하였습니다.

```csharp
lock (_lock)
{
    _instance = Object.FindAnyObjectByType<T>();
    if (_instance != null){
        MonoBehaviour mb = _instance as MonoBehaviour;
        if (mb.transform.parent != null)
            mb.transform.SetParent(null);
        /* 싱글톤 생성 */
    }
    else{
        /* 싱글톤 생성 */
    }
}
```

## 세션 복구 시스템

Web 게임 특성상 새로고침을 하게 되면 씬을 재로딩하게 됩니다. 이때 유저의 상태를 저장하지 않고 로딩하게 되면 다음 단계의 정보를 미리 알 수 있거나 성공까지 무한 반복할 수 있는 문제가 발생합니다. 때로는 디펜스 게임에서 배치를 다시 해야하는 등 불편함이 증가하기도 합니다. 이러한 문제를 해결하기 위해 상태 변경 시에 유저 매니저에 현재 상태를 저장하고 이를 기반으로 씬을 로드하도록 하였습니다.

```csharp
public void CheckAndRecoverySession()
{
    GameState lastState = GetLastSavedState();
    switch (lastState)
    {
        case GameState.Preparation:
        case GameState.Battle:
            _transitionCoroutine = StartCoroutine(RecoveryTransitionRoutine("Defense"));
            break;
        case GameState.PostStage:
            LoadPostStageScene();
            break;
        /* 상태별 동작 */
    }
}
```

다만 switch문으로 작성된 기존 코드는 개방/폐쇄 원칙(OCP)를 위반하는 구현 방식이었기에 Dictionary 기반 상태-핸들러 매핑 방식으로 코드를 리팩토링 하였습니다.

```csharp
private Dictionary<GameState, Action> _recoveryHandlers;

void Awake()
{
    Action recoverToBattle = () => StartCoroutine(RecoveryTransitionRoutine("Defense"));

    _recoveryHandlers = new Dictionary<GameState, Action>
    {
        { GameState.Preparation, recoverToBattle },
        { GameState.Battle,      recoverToBattle },
        { GameState.PostStage,   LoadPostStageScene },
        /* 상태별 동작 */
    };
}

public void CheckAndRecoverySession()
{
    GameState lastState = GetLastSavedState();
    if (_recoveryHandlers.TryGetValue(lastState, out Action handler))
        handler();
}
```

## 디펜스 기능 총괄

1. 유닛 배치

   <!-- 배치 및 배치 이동 gif -->

   UI의 배치 상태를 월드에 즉각 반영할 경우, 배치를 변경할 때마다 유닛을 생성/파괴해야 합니다. 이를 `UIGridController`에서 배치 상태를 저장하고 배치 패널이 닫힐 때 `SyncDeploymentWithWorld()`를 호출하는 단방향 동기화 구조로 구현하여, 오브젝트의 생성/파괴를 최소화하고 동기화 시점을 일원화 했습니다. 또한 유닛 생성 시에 고유 ID를 부여하고 UI 아이콘과 월드 오브젝트를 매핑하는 것으로 재배치 시에 오브젝트를 파괴·재생성하지 않고 이동시켜 버프·HP 등 컴포넌트 상태를 보존하였습니다.

   ```csharp
   public void SyncDeploymentWithWorld()
   {
       var currentDeployment = UIGrid.GetCurrentDeploymentWithIds();

       /* UIGridController에서 제거된 유닛: 배치 취소 (월드에서 제거) */
       var unitsToRemove = _activeUnits.Keys
           .Where(name => !currentDeployment.ContainsKey(name)).ToList();
       foreach (var name in unitsToRemove)
           StartCoroutine(RetreatAndDestroy(_activeUnits[name]));

       /* UIGridController에 있는 유닛: 배치 이동 or 신규 배치 */
       foreach (var item in currentDeployment)
       {
            // 배치 이동
           if (_activeUnits.TryGetValue(item.Key, out GameObject existing))
               StartCoroutine(TransitionUnit(existing));
            // 신규 배치
           else
               StartCoroutine(DeployUnit(item));
       }
   }
   ```

2. 사정거리 인디케이터

   <!-- 누적 사정거리 gif -->

   UI에서 유닛 배치 시에 사정거리를 보여주지 않을 경우, 보수적인 유닛 배치만이 가능하기 때문에 배치에서 전략적 요소를 강화하기 위해서는 사정거리를 보여줄 필요가 있었습니다. 다만 각 유닛마다 크기를 특정 값으로 저장할 경우, 밸런스 패치 등으로 서버에서 값을 수정할 때마다 클라이언트도 함께 수정할 필요가 있었습니다. 이에 가장 짧은 사정거리를 가지는 방패병 유닛을 기준으로 인디케이터 크기를 계산하고 다른 유닛에 적용하는 방식을 사용했습니다. 또한 버프 등으로 증가한 사거리는 추가적인 레이어를 추가하여 기본 사거리와 증가한 사거리를 시각적으로 구분하여 버프의 효과를 확인할 수 있도록 구성하였습니다.

   ```csharp
   float baseScale      = (unitRange / shieldRange) * 1.4f;
   float effectiveRange = unitRange * (1f + percentSum) + flatSum;
   float effectiveScale = (effectiveRange / shieldRange) * 1.4f;

   if (effectiveScale > baseScale)
       SpawnIndicatorObject(bonusRangeIndicatorPrefab, uiCoord, effectiveScale);
   SpawnIndicatorObject(rangeIndicatorPrefab, uiCoord, baseScale);
   ```

3. 오브젝트 풀 기반 스폰 시스템

   압도적인 전쟁 경험을 제공하는 것을 컨셉으로 하였기 때문에 적게는 300마리에서 많게는 1500마리가 넘는 적 유닛이 필요했습니다. 하지만 웹 게임 특성상 브라우저가 점유 중인 리소스를 공유하기 때문에 유닛 생성/파괴에 드는 가비지 컬렉션 비용을 더 민감하게 처리할 필요가 있다고 판단되었습니다. 이에 웨이브에서 등장하는 각 유닛의 40% 가량을 풀에 미리 생성하고 반납 이벤트와 Pending Queue 방식의 스폰 시스템으로 문제를 해결하고자 하였습니다.

   ```csharp
    int poolSize = Mathf.CeilToInt(enemyData.count * poolFillRatio);    // 풀 초기화

    private void SpawnEnemy(int unitId, int grade)
    {
        // Get() 실패 시 pending 증가
        GameObject obj = enemyObjectPool.Get(unitId);
        if (obj == null)
        {
            _pendingSpawn[unitId]++;
            return;
        }

        ApplyGrade(obj, unitId, grade);
    }

    // 적 유닛 반납 시 pending 처리
    private void OnEnemyReturnedHandler(int unitId)
    {
        if (_pendingSpawn[unitId] <= 0) return;

        _pendingSpawn[unitId]--;
        SpawnEnemy(unitId, _unitGrades[unitId]);
    }
   ```

## 탐사 컨텐츠 일부 구현

다회차 플레이를 즐기는 과정에서 한 회차의 플레이를 다양하게 즐길 수 있는 방법은 랜덤성 있는 컨텐츠를 추가하는 것이라고 생각했습니다. 이에 탐사라는 선택지 기반 컨텐츠를 통해 방어전에 랜덤성을 부여하고 세계관을 은연 중에 주입하며 몰입감을 높이고자 했습니다. 다만 해당 컨텐츠의 수가 많아야 의도한 바에 따라 동작하기 때문에 담당자 1인에게 모든 것을 맡기는 것은 일정상 무리가 있어, 컨텐츠의 일부를 위임 받아 구현하였습니다.

1.  기근 (다회차 지속 디버프)

     <!-- 기근 이미지 -->

    기근 이벤트는 소비 식량이 n번의 방어전 동안 2배가 되는 지속성 디버프로, 남은 횟수의 차감 시점을 식량의 소비 시점(방어전 시작)과 동기화하였습니다. 이는 저장/로드 시점을 일원화함으로써 새로고침 등 scene의 재로드 시에 횟수 차감 없는 식량의 소비나 식량 소비 없는 횟수 차감 등의 버그 상황을 방지하기 위함이었습니다.

2.  마력 안개 지대 (연출 효과 추가)

     <!-- 마력 안개 이미지 -->

    마력 안개 이벤트는 성공/실패에 따라 특정 스탯의 버프 혹은 디버프가 추가되고 결과와 무관하게 다음 방어전에서 안개 연출이 등장합니다. 연출과 스탯을 하나의 플래그로 묶을 경우, 성공/실패/우회라는 세 선택지에 따라 분기처리가 복잡해지기 때문에 이를 2가지 채널을 분리하여 처리하였습니다.

    ```csharp
    stateManager.pendingFogEffect = true;  // 연출은 상시 동작

    switch (resolutionPath)
    {
         // 성공
        case RiskSuccess:
            stateManager.pendingScoutBattleBuffs.Add(SuccessBonus);
            break;
         // 실패
        case RiskFailure:
            stateManager.pendingScoutBattleBuffs.Add(FailPenalty);
            break;
         // 우회 (연출만 등장)
        default:
            break;
    }
    ```

    <!-- 마력 안개 연출 gif -->

    안개 연출은 유니티의 Particle System을 이용하여 구현하였으나 디폴트로 사용되는 Alpha Blended Premultiply 쉐이더가 WebGL에서 지원하지 않아 안개가 그려지지 않는 문제가 발생하였습니다. 안개는 빛의 영향을 받지 않으며 WebGL에서는 가벼운 쉐이더가 필요했기에 Unlit 쉐이더를 기반으로 머티리얼을 새롭게 구현하고 적용하여 문제를 해결하였습니다.

3.  인사 이동 (보유 병력 이전)

     <!-- 인사 이동 이미지 -->

    방어전에서 사망한 유닛은 보유 유닛 풀에서 영구적으로 제거되기 때문에 한 방어전에서 주요 병력을 전부 소진하였고 충분한 골드를 남겨두지 않았다면 다음 방어전이 굉장히 힘든 경우가 있었습니다. 이에 보유 중인 병력 중 랜덤한 병과를 선택하여 다른 병과로 변경시키는 이벤트를 구현하였습니다. 해당 이벤트는 앞선 상황에서 뿐만 아니라 가격이 낮은 병과의 병력을 가격이 높은 병과의 병력으로 변경시킬 수도 있는 복불복 컨텐츠의 역할을 하기도 합니다.

    ```csharp
    // 대상 후보: 보유 수량 > 0인 병과
    List<int> sourceIndices = new List<int>();
    for (int i = 0; i < maxCount; i++)
        if (owned[i] > 0) sourceIndices.Add(i);

    int sourceIndex = sourceIndices[Random.Range(0, sourceIndices.Count)];

    // 타깃 후보: 대상을 제외한 전체
    List<int> targetIndices = new List<int>();
    for (int i = 0; i < maxCount; i++)
        if (i != sourceIndex) targetIndices.Add(i);

    // 대상의 잔량을 초과하지 않도록 클램프
    int actualTransfer = Mathf.Min(settings.transferCount, owned[sourceIndex]);
    ```

// AES-GCM 암호화
public static (string ivBase64, string dataBase64) Encrypt(string plaintext, byte[] key)
{
    byte[] iv = new byte[12];
    new SecureRandom().NextBytes(iv);  // 매 요청마다 새 IV 생성

    var cipher = new GcmBlockCipher(new AesEngine());
    cipher.Init(true, new AeadParameters(new KeyParameter(key), 128, iv));

    byte[] plaintextBytes = System.Text.Encoding.UTF8.GetBytes(plaintext);
    byte[] output = new byte[cipher.GetOutputSize(plaintextBytes.Length)];
    int len = cipher.ProcessBytes(plaintextBytes, 0, plaintextBytes.Length, output, 0);
    cipher.DoFinal(output, len);

    return (Convert.ToBase64String(iv), Convert.ToBase64String(output));
}

private string TryEncryptBody(string endpoint, string jsonBody)
{
    if (IsCryptoExcluded(endpoint) || !SessionKeyManager.IsReady) return null;
    var (iv, data) = AesGcmCrypto.Encrypt(jsonBody, SessionKeyManager.SessionKey);
    return $"{{\"iv\":\"{iv}\",\"data\":\"{data}\"}}";
}

private string TryDecryptResponse(string endpoint, string response)
{
    if (IsCryptoExcluded(endpoint) || !SessionKeyManager.IsReady) return response;
    var payload = JsonUtility.FromJson<EncryptedPayload>(response);
    return AesGcmCrypto.Decrypt(payload.iv, payload.data, SessionKeyManager.SessionKey);
}

## WebGL 최적화

유닛 스폰에 오브젝트 풀링을 적용한 뒤에도 3500이라는 비정상적인 드로우콜 수치와 유니티 내부적인 메모리 사용량을 제외하고도 60mb 정도의 높은 메모리 사용량이 나오고 있었습니다. 이에 다방면에서 문제를 확인한 결과, 일부 오브젝트에서 GPU Instancing 기능이 적용되지 않은 상황이었고 아군 유닛의 애니메이션 처리에 문제가 있었습니다.

우선 Terrain에 사용되는 각종 오브젝트에 GPU Instancing을 적용하고 사용 중인 texture, normal map, material 등이 필요 이상으로 크게 설정되어있던 것을 Terrain의 크기에 맞춰 감소시켰습니다. 또한 shadowmask의 적용 거리를 어색하지 않은 수준에서 최대한 감소시키는 것으로 빛으로 인한 연산량을 크게 감소시킬 수 있었습니다.

아군 유닛은 1개체임에도 하나의 부대 느낌을 주기 위해 13개의 개별 오브젝트로 존재했는데 기존에는 13개의 각 오브젝트에 animator가 부착되어 동작하고 있었습니다. 처음에는 CPU 연산의 효율을 위해 해당 시스템을 단일 animator에서 각각의 sprite를 바인딩하고자 했으나 이 경우, 짧은 개발 기간 안에 이미 만들어둔 아군 유닛의 애니메이션을 전부 수정할 필요가 있었습니다. 일정상 이는 불가능하다고 판단되어, 마스터 오브젝트에만 animator를 부착하고 자식 오브젝트는 별도의 코드를 통해 마스터 오브젝트의 색상과 이미지를 LateUpdate로 가져오는 방식으로 방법을 채택하였습니다.

```csharp
public class SpriteSync : MonoBehaviour
{
    public SpriteRenderer masterRenderer;
    private SpriteRenderer myRenderer;

    void Awake() => myRenderer = GetComponent<SpriteRenderer>();

    void LateUpdate()
    {
        myRenderer.sprite = masterRenderer.sprite;
        myRenderer.flipX  = masterRenderer.flipX;
        myRenderer.color  = masterRenderer.color;
    }
}
```
