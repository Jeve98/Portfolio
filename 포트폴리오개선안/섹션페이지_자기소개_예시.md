# 섹션 페이지 자기소개 예시

## 작성 배경

포트폴리오의 개발 페이지와 기획 페이지에는 현재 자기소개가 없다.  
직군별 섹션 URL을 직접 제출하는 전략을 쓸 경우, 채용 담당자는 메인 페이지를 거치지 않고 해당 섹션에 바로 들어온다.  
자기소개 없이 프로젝트 목록만 보게 되면 지원자가 누구인지 파악할 맥락이 없다.

**핵심 원칙:**  
메인 자기소개를 그대로 복붙하지 않는다.  
개발 페이지는 개발 역량 중심으로, 기획 페이지는 기획 역량 중심으로 각각 다르게 작성한다.  
분량은 짧게 — 3~5줄이면 충분하다.

---

## 개발 섹션 페이지용 자기소개

```
전연욱
삼성 청년 SW 아카데미(SSAFY) 수료

Unity / C# · Phaser · Django · Vue.js
멀티플레이 네트워크 최적화와 성능 튜닝, 그리고 설계 구조에 집중하는 개발자입니다.
팀 프로젝트에서 단순히 기능을 구현하는 것에 그치지 않고,
기술적 선택의 근거를 언어로 설명하고 수치로 증명하는 것을 지향합니다.

게임 기획 경험도 보유하고 있어 기획자와의 커뮤니케이션에 강점이 있습니다.

이메일: jadam41817@gmail.com
기술 블로그: https://jadam41817.tistory.com/
```

**포인트 설명:**
- "멀티플레이 네트워크 최적화, 성능 튜닝, 설계 구조"는 마네킹과 프라가라흐에서 실제로 한 일을 그대로 키워드화한 것이다. 빈말이 아니라 뒤의 프로젝트들이 근거가 된다.
- "기술적 선택의 근거를 언어로 설명하고 수치로 증명"은 포트폴리오 전체를 관통하는 강점이므로 자기소개에서 선언해두면 읽는 사람이 프로젝트를 그 시각으로 읽게 된다.
- 기획 경험을 마지막에 한 줄로 언급하면 "개발자인데 기획도 이해한다"는 강점으로 작동한다. 기획 섹션 링크 전체를 보여주는 것보다 이 편이 낫다.

## 기획 섹션 페이지용 자기소개

```
전연욱
삼성 청년 SW 아카데미(SSAFY) 수료

게임 시스템 기획 · 장르 트렌드 분석 · GDD 작성
플레이어가 무엇에 몰입하는지를 분석하고, 그것을 시스템으로 구현하는 기획자입니다.
개발 경험을 바탕으로 구현 가능성을 고려한 기획을 지향하며,
기획서 작성 단계부터 개발자와의 협업 구조를 염두에 두고 설계합니다.

이메일: jadam41817@gmail.com
기술 블로그: https://jadam41817.tistory.com/
```

**포인트 설명:**
- "장르 트렌드 분석"은 노룸베가에서 코로나 이후 게이머 행동 변화를 분석한 것, 던파 사례 등이 근거가 된다.
- "구현 가능성을 고려한 기획"은 개발 경험이 있는 기획자임을 차별점으로 내세우는 핵심 문장이다. 기획자 직군에서 "개발을 모르는 기획자"에 대한 팀 리더의 피로감이 있기 때문에, 이 한 줄이 실질적인 어필 포인트가 된다.
- "기획서 작성 단계부터 개발자와의 협업 구조를 염두에 두고 설계"는 추상적으로 보일 수 있지만, 펌블의 플래그 기반 설계에 코드 예시를 첨부한 것이 구체적인 근거가 된다.

## 두 자기소개의 차이 요약

| 항목 | 개발 페이지 | 기획 페이지 |
|------|------------|------------|
| 강조 역량 | 네트워크 최적화, 성능 튜닝, 설계 구조 | 트렌드 분석, 시스템 기획, GDD 작성 |
| 기술 스택 언급 | 있음 (Unity, Phaser, Django, Vue) | 없음 (불필요) |
| 크로스 역량 언급 | 기획 경험 있음 (한 줄) | 개발 경험 기반 기획 (강점으로 활용) |
| 톤 | 기술 중심, 수치/근거 강조 | 플레이어 이해 중심, 협업 강조 |

## 배치 위치 제안

각 섹션 페이지 진입 시 보이는 **상단 배너 바로 아래**, 프로젝트 카드 목록 위에 배치한다.  
시각적으로 너무 길지 않도록 3~5줄 텍스트 + 연락처 정도로 유지한다.  
메인 페이지의 자기소개보다 짧아도 되고, 짧은 것이 오히려 읽기 편하다.
