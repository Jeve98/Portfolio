## 기획 의도

현대 게이머의 평균 플레이 타임이 감소하는 추세를 반영하여, 로그라이크 장르의 핵심 요소인 **짧은 단판 · 매회 새로운 경험 · 반복 플레이 유도**를 비대칭 PVP에 접목했다.

증강 시스템을 통해 매 판마다 다른 빌드를 경험하도록 하여 플레이 템포를 가속화하고 리플레이어빌리티를 확보했다.

## 구현 상세

### 1. 살인마 스킬 4종

**더미 설치**
맵의 정해진 구역에 마네킹을 배치하는 스킬. 설치 가능 위치 리스트를 순회하여 가장 가까운 유효 지점을 자동 선택하도록 구현했다.

**전이**
더미 마네킹만 렌더링하는 전용 카메라를 별도 구성했다. 맵의 안개로 인한 시야 차단을 막기 위해 커스텀 쉐이더를 제작하여 적용했다.

**교란**
전이 스킬이 애니메이션으로 쉽게 간파되는 문제를 해결하기 위해, 교란 사용 시 모든 더미에 동시에 애니메이션을 재생하여 실제 전이와 구분 불가능하게 설계했다.

**위장**
1인칭 시점의 제한된 색적 능력 보완을 위해 3인칭 시점 전환 기능을 추가했다. 근처 생존자의 효음 신호를 차단하여 마네킹으로 위장 가능하도록 구현했다.

### 2. 스폰 시스템 최적화

기존 방식은 position(x, y, z)과 rotation(x, y, z) 총 6개 값을 매 프레임 네트워크로 전송했다.  
분석 결과 `position.y`, `rotation.x`, `rotation.z`는 게임 중 변하지 않는 고정값임을 확인했다.

| 항목 | 최적화 전 | 최적화 후 |
|------|-----------|-----------|
| 전송 값 수 | 6개 | 3개 |
| 네트워크 트래픽 | 기준 | **50% 감소** |

살인마는 `position.y = 108f`, 생존자는 `position.y = 1f`로 고정하고,  
rotation은 Y축 값만 변수로 처리했다.

```csharp
// 핵심 로직 발췌
public SpawnData GetKillerSpawnData() { ... }
public SpawnData GetSurvivorSpawnData(int spawnOrder) { ... }
public void PlayerJoined() { /* 역할에 따른 프리팹 스폰 */ }
```

### 3. 상호작용 시스템 — 인터페이스 선택 근거

```csharp
public interface IInteractable
{
    string GetInteractionText();
    string GetAnimationTrigger();
    void OnInteract();
}
```

상호작용 대상(파괴, 정화, 뛰어넘기)은 **부모-자식 수직 확장이 아닌 수평 확장** 관계다.  
C#의 단일 상속 제약 하에서 `NetworkBehaviour`와 `MonoBehaviour`를 동시에 상속해야 하는 케이스가 존재했기 때문에, 추상 클래스 대신 인터페이스를 선택했다.

---

### 4. 증강 시스템 — 추상 클래스 선택 근거

```csharp
public abstract class AbilityBase : NetworkBehaviour
{
    public abstract void Activate();   // 누락 시 치명적 → 강제화
    protected virtual void Awake() {}  // 방어 코드 성격 → 유연성 부여
}
```

`Activate()`는 미구현 시 게임이 동작하지 않으므로 추상 함수로 강제화했다.  
`Awake()`는 선택적 초기화 용도이므로 가상 함수로 오버라이드 여지를 남겼다.

증강 시스템은 기능이 계층적으로 확장되는 구조이므로 인터페이스가 아닌 추상 클래스를 선택했다.  
(상호작용 시스템과 설계 기준이 다른 이유)

### 5. Occlusion Culling 최적화

Unity의 기본 Frustum Culling만으로는 성능이 부족했다.  
AI로 생성한 3D 메시가 많아 vertex가 복잡하고 맵 규모도 상당했기 때문이다.

Occlusion Culling을 추가 적용하여 카메라 뷰 내 가려진 오브젝트도 렌더링에서 제외했다.

| 항목 | 수치 |
|------|------|
| 적용 전 | 13 fps |
| 적용 후 | 63.6 fps |
| 성능 향상 | **약 390% 향상** |

약 5주라는 개발 기간을 고려해 개별 LOD 적용 대신 공간 단위 Occlusion Culling을 선택했다.  
비용 대비 효과가 가장 높은 방법이었다.

---

### 6. Jitter 완화

특정 증강 획득 시 Jitter가 발생했다.  
원인: 서버와 클라이언트가 서로 다른 시간축으로 상태를 변경하면서 네트워크 지연이 누적되었다.

해결 방법:
1. RPC로 상태값을 추가 확정하는 방어 코드 삽입
2. 동기화 기준을 서버로 일원화
3. 증강 적용을 동기화 확인 후 의도적으로 지연 처리

결과: Jitter 발생 안정화 확인.
